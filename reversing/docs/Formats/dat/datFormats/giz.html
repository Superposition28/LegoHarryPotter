.GIZ / .PGIZ (World Gizmos, Token Spawns & ComplexGizmo)

Transition Pinpointed Empirically: TCS–LOTR use fixed-width string sections; Marvel 1 (547) onward use .CC4HSERHSER ComplexGizmo referencing level .led files.

LEGO Harry Potter: Years 1–4, Years 5–7 & 2024 Collection · Interactive Gameplay · Classic String Sections → Era 4 .CC4HSER

World interactive gizmo tables (switches, vehicle pads, studs, collectible tokens). Transitioned sharply between LOTR (str32) and Marvel 1 (.CC4HSER ComplexGizmo referencing .led).

Extensions
.giz (all PS3 titles), .pgiz (TCS 1 file)
Classic Format
u32le count + fixed 32-byte ASCII section headers (TCS–LOTR)
Era 4 Format
.CC4HSERHSER + "ROTV" + linked .led path + "ComplexGizmo" records (Marvel 1–Dim)

Two-Generation Binary Split

.giz Legacy vs Era 4 ComplexGizmo
Generation Titles Header & Content
Classic (Era 2–3c) TCS (264) → LOTR (278) u32le count + 32-byte fixed ASCII section tags, world coordinates, and gizmo parameter structs.
Era 4 (.CC4HSER) Marvel 1 (547), Hobbit (416), Dimensions (523) Outer u32be sz + .CC4HSERHSER + target .led string (e.g. builderhubwebs_temp.led) + "ROTV" + repeated ComplexGizmo instance blocks.

Standalone Clean-Room Parser Pseudocode

function ParseGiz(buf):
    if buf[4:8] == b".CC4":
        return {era: "CC4HSER", count: CountTag(buf, b"ComplexGizmo")}
    return {era: "Classic", section_count: ReadU32LE(buf, 0)}
