Binary Header & 28-Byte Entry Table Layout (Little-Endian)

PAK / PAC / FPK Container Format (0x1234567A)
Offset Size Type Field Description
0x00 4 u32le magic Constant 0x1234567A (bytes 7A 56 34 12).
0x04 4 u32le file_count Number of packed files (1..2000+).
0x08 4 u32le total_size Total file byte size.
0x0C 4 u32le checksum 0x12345678 + sum(ord(ch.upper())) across path/names.
0x10..0x17 8 u32le[2] unk1, unk2 Usually 0, 0 (or 0xCCCCCCCC sentinel in early LSW2).
0x18 + i*28 28 struct PakEntry[i] offset(u32le), size(u32le), flags(u32le), name_rel(u32le), h1(u32le), h2(u32le), pad(u32le).

Cross-Format Relationships & Dependencies

Referenced By (Upstream Containers / Loaders)

  • .DAT / .HDR — Loaded from virtual filesystem; holds up to 2,495 .pak archives in Marvel 1.
  • .cd / .as — Character definitions mount *_anm.pak and alltxt.pak / *_fpk.fpk.

References (Downstream Assets / Sub-Formats)

  • .an3 / .an4 Animations — Uncompressed or Deflate_v1.0 skeletal clips bundled inside .pak/.pac.
  • .txt / .scp Scripts — Abilities and config tables (chars\abilities\*.txt) packed inside .fpk.

Filtering, Edge Cases & Unresolved Fields

  • Entries inside .pak/.pac/.fpk are normally stored raw, EXCEPT .an4 members in Marvel 1+ which retain their internal Deflate_v1.0 header inside the pack.

Standalone Clean-Room Parser Pseudocode

function ParsePak(buf):
    magic, cnt, total, csum = ReadU32LE4(buf, 0)
    if magic != 0x1234567A: raise NotPak
    entries = []
    for i in 0 .. cnt - 1:
        off, sz, flg, name_off, h1, h2, _ = ReadU32LE7(buf, 24 + i * 28)
        name = ReadNullAscii(buf, name_off)
        entries.append({name: name, data: buf[off : off + sz], flags: flg})
    return entries
