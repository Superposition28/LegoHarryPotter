Binary Layout Comparison (TCS BE vs BM1/BM2 LE)

.sfx Binary Cue Table Layouts
Game / Version Header Fields (0x00..0x0B) Cue Record Layout
TCS (v2 BE) u32be 2, u32be cue_count (0x81), u32be val (0xB7) u16be slen + ASCII cue name + u8 bank/category ID (1, 2...).
BM1 (v3 LE) u32le 3, u32le list_count (14), u32le total_refs (30) u16le slen + ASCII cue name + u16le category ID (2, 3...).
BM2 (v5 LE) u32le 5, u32le list_count (11), u32le total_refs (23) u16le slen + ASCII cue name + u16le flags + trailing cue property floats ("TB", 1.0f...).

Cross-Format Relationships & Dependencies

Referenced By (Upstream Containers / Loaders)

  • .led / .sf / .scp — Gameplay triggers fire named sound cues in the current level .sfx.

References (Downstream Assets / Sub-Formats)

  • .msf / .xma / .audio — Resolves cue names to sample filenames / banks in audio/samples/.

Filtering, Edge Cases & Unresolved Fields

  • Endian Flip After TCS: TCS PS3 wrote .sfx big-endian (00 00 00 02), whereas BM1+ standardized on little-endian even on PS3.

Standalone Clean-Room Parser Pseudocode

function ParseSfx(buf):
    is_be = (ReadU32BE(buf, 0) <= 5)
    ver, cnt, refs = ReadU323(buf, 0, be=is_be); p = 12; cues = []
    for _ in 0 .. cnt - 1:
        if p + 2 > len(buf): break
        slen = ReadU16(buf, p, be=is_be); p += 2
        nm = buf[p:p+slen].decode("ascii", "replace"); p += slen
        flg = buf[p] if is_be else ReadU16LE(buf, p); p += (1 if is_be else 2)
        cues.append((nm, flg))
    return {version: ver, cues: cues}
