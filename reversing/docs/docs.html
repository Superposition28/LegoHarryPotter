Documentation Guide & Format Analysis Conventions

Project: LEGO Harry Potter Reversing & Format Documentation

1. Game-Scoped Documentation Rule

This documentation suite covers formats, archives, and extracted assets specific to LEGO Harry Potter (Years 1–4 using NXG HSEM v0x04/v0x05, Years 5–7 using HSEM v0x2E/v0x2F, console PakDat v1.01 LZ2K, and the 2024 PC Collection .datwin LZHAM releases). It follows the two-tier LEGO reversing documentation hierarchy:

  • Scope of This Game Documentation: Pages under Formats/ document only the format versions present in LEGO Harry Potter releases. Earlier Classic Nu2 or later Era 4/5 TT Games variants not shipped in LEGO Harry Potter are kept to minimal notes so an implementer can write a parser exclusively for LEGO Harry Potter without supporting other games.
  • Parent Shared LEGO Documentation (../../reversing/docs/Travellers_Tales/): Combines format variants across all Traveller's Tales titles and engine generations. Consult the parent docs when cross-title compatibility or full historical lineage is required.

2. Two Complementary Documentation Trees

  1. Format Analysis (Formats/): Follows binary format origins from executable and archive containers (.xex, .bin/ELF, .exe, .dat/.datwin) to extracted formats (datFormats/).
  2. Game Files & Asset Use (Files/): Documents directory hierarchies, asset inventories across PS3/Xbox 360/PC Collection, sound banks, character definitions, and level scripts through a combined virtual filesystem.

3. Expected Level of Detail (Standalone Clean-Room Standard)

Every understood format page in this module must be a complete, standalone specification capable of guiding a clean-room parser or converter implementation for LEGO Harry Potter without inspecting RemakeEngine source code. Format pages must include:

  • Exact signatures, version constants, and mixed-endianness rules (big-endian console/HSEM tables vs. little-endian PC Collection float vertex data).
  • Full byte-offset structure tables, attribute encoding tables, and mathematical decoding formulas.
  • Shared-buffer back-reference resolution, shadow-pass skipping, LOD/breakup filtering, and winding rules.
  • Complete, end-to-end pseudocode covering binary parsing through final triangle reconstruction.
